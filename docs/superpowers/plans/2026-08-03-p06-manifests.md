# P06.4 Manifest Graph and Markdown Frontmatter Plan

Base: `origin/main@54da096`

## Goal

Close P06 with deterministic Markdown frontmatter and a schema-validated,
reference-complete manifest graph that can drive due-state and reconciliation
without fetching LFS objects.

## Assumptions

- Current 1.1 source, document, conversion, and storage-reference schemas remain
  authoritative; no schema bump is needed.
- Only `provenance_state=current` participates in the strict graph.
- Manifest publication is materialize-only beneath an explicit `temp_root`.
- LFS `storage_object_id` is `sha256:<artifact sha256>`; pointer-file bytes
  are never an artifact identity.
- Frontmatter bytes are part of output SHA and metadata bytes are bound through
  `options_sha256`, hence through fingerprint and conversion ID.

Files:

- Create `scripts/rki_pipeline/conversion/frontmatter.py`
- Modify `scripts/rki_pipeline/conversion/service.py`
- Modify `scripts/rki_pipeline/conversion_cli.py`
- Modify `tests/test_conversion.py`
- Modify `tests/test_conversion_service.py`
- Modify `tests/test_cli_entrypoints.py`

RED:

- Require immutable, validated document metadata.
- Render exact ordered YAML-compatible frontmatter before first page marker.
- Reject control characters, machine paths, unsafe URLs, invalid dates/types,
  caller-provided tags, and metadata/document/intent mismatches.
- Assert title/DOI/source URL changes alter options hash, fingerprint, conversion
  ID, output hash, and output bytes.
- Assert source PDF and marker count remain unchanged.

GREEN:

- Add one frozen `MarkdownMetadata` value object and one deterministic renderer.
- Derive `source_pdf` from canonical PDF/Markdown repository paths.
- Reuse canonical path, source/document identity, stable JSON, and conversion
  fingerprint helpers.

## Task 2 — Pure manifest graph

Files:

- Create `scripts/rki_pipeline/manifests.py`
- Create `tests/test_manifests.py`

RED:

- Validate every payload against its registered schema.
- Reject duplicate primary IDs, dangling source/document/bitstream/conversion
  links, conflicting hashes/rights decisions, invalid supersession pairs/cycles,
  invalid same-content aliases/cycles, orphan conversions/references, duplicate
  paths/storage objects, and LFS pointer/object SHA confusion.
- Accept exactly linked source PDF and converted Markdown references.
- Produce stable tuples independent of input order.

GREEN:

- Build four ID maps once.
- Validate source aliases and document supersession as directed acyclic,
  reciprocal relationships.
- Bind document to source via source ID and bitstream ID.
- Bind conversion to document/source bitstream/SHA.
- Bind PDF storage SHA to source SHA and conversion storage SHA to output SHA.
- Require LFS object ID `sha256:<reference sha256>`.

Verify:

```bash
python -m pytest -q tests/test_manifests.py -k graph
```

RED:

  catalog containing count, byte size, and SHA-256.
- Reject malformed JSON, blank lines, non-canonical JSON, unregistered files,
  symlinks, oversized lines/files, catalog drift, and graph drift.
- Replace one sentinel-owned manifest root transactionally; no append.

- Keep collection layout:

  `catalog.json`.
